# 04 — Discovery Agent Specification

## Purpose

Discovery is the only normal path where an LLM makes UI decisions. It must genuinely operate the live surface and leave enough structured evidence to compile a reusable capability.

The discovery request may include **explicit invocation parameter bindings** in addition to the required natural-language goal + target, e.g. `member_id=M-10001`. This is deliberate: the calling agent often already has structured entity values, and providing the binding lets the executor fill the real value while the model refers only to `member_id`. It also makes PII redaction and later artifact parameterization deterministic. The goal is still natural language and the model must still discover the UI workflow.

## Observation payload

Every discovery turn should provide a bounded observation containing:

- current URL / named entry point
- page title
- screenshot (real current screen)
- compact visible-text summary
- semantic element inventory generated by the Playwright surface adapter
- current step number / elapsed time
- goal
- allowed action kinds and policy boundaries
- available invocation input names/types/descriptions; sensitive concrete values should not be shown to the model unless strictly necessary and must be omitted/redacted from logs

### Semantic element inventory

Assign short ephemeral references such as `e1`, `e2`, ... only for the current observation.

Example:

```json
[
  {
    "ref": "e1",
    "kind": "textbox",
    "accessible_name": "Member ID",
    "placeholder": "Enter member number",
    "text": "",
    "candidate_strategies": [
      {"kind":"label","value":"Member ID"},
      {"kind":"placeholder","value":"Enter member number"},
      {"kind":"stable_attribute","attribute":"name","value":"member_id"}
    ]
  },
  {
    "ref": "e2",
    "kind": "button",
    "accessible_name": "Search",
    "candidate_strategies": [
      {"kind":"role_name","role":"button","name":"Search"},
      {"kind":"text","value":"Search"}
    ]
  }
]
```

The LLM chooses an element ref or coordinate action. The model should not invent CSS selectors. The adapter/compiler owns robust locator extraction.

## Structured LLM action contract

Use strict tool use/structured output where current Anthropic SDK supports it. Regardless, Pydantic-validate before execution.

Recommended action union:

```text
NavigateAction:
  action = navigate
  url
  rationale_summary

ClickAction:
  action = click
  element_ref OR coordinate
  rationale_summary

FillAction:
  action = fill
  element_ref
  value_source: {input_name: ...} OR safe literal
  rationale_summary

SelectAction:
  action = select
  element_ref
  value_source
  rationale_summary

ExtractAction:
  action = extract
  element_ref
  output_name
  output_type
  rationale_summary

WaitAction:
  action = wait
  milliseconds <= configured cap
  rationale_summary

DoneAction:
  action = done
  success_summary
  suggested_success_condition

RequestHumanAction:
  action = request_human
  reason_code
  message
```

Never give the model a generic `run_shell`, `evaluate_js`, `execute_python`, arbitrary network request, or raw browser-script tool.

## Discovery system prompt behavior

The runtime system prompt should tell the model:

- achieve only the supplied goal,
- use only provided UI actions,
- prefer semantic element refs,
- do not navigate outside allowed target,
- never submit an irreversible/high-risk action without explicit policy approval,
- extract outputs only when visible,
- if blocked/unsafe/ambiguous, request human rather than guess,
- when goal appears complete, emit `done` rather than continuing,
- do not expose hidden reasoning; return only concise rationale summary and structured action.

## Loop

Pseudo-flow:

```python
while not terminal:
    guard_budget()
    observation = await surface.observe()
    detect_repeated_state(observation)
    proposed = await model.next_action(goal, observation, history_summary)
    action = validate(proposed)
    policy_decision = policy.check(action, observation)

    if policy_decision.requires_human:
        return await handoff(...)
    if not policy_decision.allowed:
        record_policy_block(...)
        if blocked_is_terminal: escalate_or_fail()
        continue

    result = await surface.execute(action)
    recorder.record(observation, action, result)

    if action is done:
        independently_verify_goal_checkpoint()
        break
```

Important: do not trust `done` blindly. Validate the proposed success condition or compiler-selected checkpoint against current UI state.

## Dead-end/stuck detection

At minimum:
- max steps (default 20)
- wall-clock timeout (default 180 sec)
- same observation fingerprint repeated with same/similar action >= 3 times
- repeated execution error >= configured threshold
- policy denies multiple attempts
- LLM explicitly requests human

Create an intervention rather than an infinite loop.

## Discovery recording

Recorder stores per-step redacted facts:

- before-observation fingerprint
- screenshot path (optionally every step; at least key/failure steps)
- proposed structured action
- concise rationale summary
- policy decision
- resolved target/candidate locator strategies
- action result
- after-observation fingerprint
- output extraction metadata
- timestamps and duration

Do not store raw sensitive field values. Do not store model chain-of-thought.

## Artifact compilation

On successful discovery:

1. Validate goal success independently.
2. Drop no-op/redundant exploratory steps if safe to do so.
3. Convert ephemeral element refs to durable `TargetDescriptor`s.
4. Replace invocation-specific values with `InputValueRef`s using the discovery invocation bindings as the primary deterministic mapping.
5. Build typed output specs from successful extraction.
6. Attach checkpoints/error rules/policy metadata.
7. Validate with Pydantic schema.
8. Serialize deterministic formatted JSON.
9. Save provenance/run ID separately from raw transcript.

Compiler must fail loudly if it cannot parameterize a sensitive value or cannot create a usable locator for a required step.

## Offline/mock model

Tests should not require paid API access. Provide a deterministic fake/model adapter that returns scripted structured actions against the demo app. This does **not** replace the required real discovery evidence; it exists only for tests/local smoke runs.
